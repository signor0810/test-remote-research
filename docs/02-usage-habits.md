# 使用習慣建議（SOP）

架構可以慢慢建，**習慣今天就能改，而且它貢獻了大部分的效果**。
以下依「投資報酬率」排序，前四項做到，就算完全不寫任何自動化程式，週報也能在 15 分鐘內生出來。

---

## Tier 1：非做不可（沒有這些，後面全部無效）

### H1. 一切都帶 Jira key

| 場合 | 格式 | 例 |
|---|---|---|
| 分支 | `<type>/<KEY>-<slug>` | `feat/ABC-123-retry-backoff` |
| Commit | `<KEY>: <動詞開頭>` | `ABC-123: add exponential backoff` |
| AI session 第一行 | `[ABC-123] <一句話目標>` | `[ABC-123] 讓 retry 支援 backoff，先看現有實作` |
| Confluence 標題 | `[ABC-123] <主題>` | `[ABC-123] Retry 策略決策紀錄` |

**為什麼**：這是整個系統的關聯鍵。沒有 key 的工作在週報裡只能是「其他」。
**成本**：每次 3 秒。**收益**：週報自動分群、Jira 自動回寫、跨工具追溯全部靠它。

### H2. 一個任務一個 session

不要在同一個 session 裡橫跨兩個 Jira issue。摘要器（cursor / AP）會把兩件事揉成一段，之後拆不開。
切換任務時開新 session，成本遠低於事後人工拆解。

### H3. 收尾三行（**單項最高槓桿**）

每個 session 結束前，固定丟這句：

```
用三行總結：1) 做了什麼 2) 產出連結 3) 卡在哪 / 下一步
```

這三行**就是週報的原料**。它把「摘要的品質控制權」從摘要器手上拿回來 —— 自動摘要寫的是「對話發生了什麼」，你要的是「工作產生了什麼」，兩者不同。

> **hermes 特別注意**：三個工具中只有 hermes 沒有自動摘要。hermes 的 session **一定**要手動收尾，否則這部分產出在週報裡等於不存在。

建議把這句存成三個工具共用的 snippet / alias（例如 `/wrap`）。

### H4. 卡住 25 分鐘就記一筆 friction

不要硬幹。開一個固定的 `friction.md`（或 Confluence 頁），一行記完：

```
2026-08-21 | manual-toil | 12min | 手動比對 staging/prod 兩份 config
2026-08-22 | waiting     | 40min | 等 X 團隊回 API 規格
2026-08-22 | rework      | 25min | AP 沒有外網，套件用法要換到 cursor 重問
```

分類只有五種：`rework` / `waiting` / `manual-toil` / `context-switch` / `tool-gap`。
**這是「找自動化機會」唯一可靠的資料來源** —— 事後從 log 挖挖不出來，因為浪費時間的事通常不留痕跡。

## Tier 2：明顯有感

### H5. 工具路由，不要憑手感

> 內部程式碼 / 內部知識 → **sng-ap**（KA 是它的獨佔優勢）
> 看圖 / 吞長文件 → **hermes**（記得額度）
> 其餘寫扣、需要查外部資料 → **cursor-cli**

hermes 每週自訂 **45 次**上限，週一心裡先分配好；用超過先問自己「這題 AP 或 cursor 能不能做」。

### H6. 每天下班前 2 分鐘 flush

檢查三件事：今天的 session 都有收尾三行了嗎？friction 記了嗎？有沒有 commit 漏帶 key？
兩分鐘，但它讓週五那天不需要回想任何事。

### H7. 週報只審不寫

草稿由系統產，你只做三件事：刪掉不重要的、補上系統看不到的（會議上的口頭決定、人際協調）、確認每句話都有連結。
**若你發現自己在從零寫週報，代表 L4 的 prompt 該調了 —— 那是系統的 bug，不是你該補的工。**

### H8. Confluence 頁面加固定 label

`weekly-report` / `decision` / `runbook` / `friction`。
沒有 label，L1 就只能靠標題猜；有 label，連接器可以精準只抓需要的頁面。
決策類頁面尤其重要 —— 週報裡「本週做了什麼決定」這段完全靠它。

---

## Tier 3：長期複利

### H9. 每個專案一份 project brief

`docs/brief-<KEY>.md`：目標、架構約束、命名慣例、常踩的坑。
每次開 session 貼進去（或讓工具自動載入）。它同時解掉「跨三個工具重複貼 context」這個高頻 friction。

### H10. 內部資訊邊界，人為守住

`sng-ap` 沒有外網是刻意設計的邊界。不要把 AP 裡的內部程式碼片段貼去 cursor 或 hermes 求解 —— 那等於繞過了那道邊界。
需要外部知識時，把問題**抽象化**後再問外部工具（問模式，不問你的實作）。

### H11. 每月看一次排行榜，只做一項

自動化機會排行榜出來後，只挑分數最高的一項動手。做完下個月再挑。
同時開三個自動化專案，通常結果是三個都爛尾。

## 每週節奏一覽

| 時間 | 動作 | 耗時 |
|---|---|---|
| 週一 09:00 | 分配本週 hermes 額度；掃過 Atlassian/Outlook 更新，只留與自己 Jira key 相關者 | 10 min |
| 每日 · 每個 session 結束 | 收尾三行（H3） | 30 sec |
| 每日 18:00 | flush 檢查（H6） | 2 min |
| 隨時卡住 | 記一筆 friction（H4） | 20 sec |
| 週五 16:00 | 系統產草稿 | 0（自動） |
| 週五 16:30 | 審稿、補系統看不到的、送出 | 10 min |
| 每月最後一個週五 | 看排行榜，挑一項做 | 30 min |
